# Reproduction and evidence handling

## Three different operations

| Operation | Required material | What it establishes |
| --- | --- | --- |
| Analyze published answers | Compact evidence under `experiments/evidence/` and independent ratings | An evaluation of the recorded proposals |
| Run a fresh replication | Current source, pinned inputs, private runtime configuration, new output directory | A new sample under the recorded current protocol |
| Resume a historical collection | Original source/build/settings, complete original run archive and its caches | Continuation of that historical collection |

The compact publication export is not a resumable run archive. Source cleanup does not change an old run's code identity. Provider seeds and temperature zero do not guarantee identical future outputs.

## Retained inputs and commands

The checked-in `genesis/creative-preview.json` is byte-pinned. Its SHA-256 is `af468c3b2a08171e636b4dd4b621bb5d56a2eb609e9df3258292f9c5cc971ba2`. It contains 419 and 369 text turns from the two official source conversations. Do not translate or edit this input after collection.

Other LoCoMo-derived fixtures are generated by the Rust tools from the official dataset:
https://github.com/snap-research/locomo/blob/main/data/locomo10.json .
The preparer records and checks source fingerprints. Image data, QA answers and generated summaries are not memory exposure.

```bash
bash experiments/genesis/tools.sh prepare-preview /path/to/locomo10.json /fresh/path/preview.json
bash experiments/genesis/tools.sh prepare-life /path/to/locomo10.json /fresh/path/life-economy.json --profile economy
bash experiments/genesis/tools.sh prepare-life /path/to/locomo10.json /fresh/path/life-full.json --profile full
```

Use the protocol-specific launcher and a fresh result directory. `--prepare-only` performs design/input setup without model calls; continuation then uses the same options with `--resume`. Not every command shares the same flags: follow its retained protocol. A successful mock cannot qualify a model or support a scientific result.

Runtime keys stay in an ignored local configuration or environment variables. HTTP ceilings count attempts, including retries; they are not monetary caps or completion guarantees. Do not change code, compiled binary, fixture, provider, model or reasoning settings during a resumable collection. Raising the permitted attempt ceiling is recorded where supported.

## Preserve paid work

Keep raw responses, HTTP start/finish records, validation errors, caches, operation journals, original manifests, checkpoints and checksums. Do not overwrite an earlier result with a new protocol. Do not edit hashes to force resumption or reset the paid attempt count.

Legacy source snapshots and interrupted-run upgrade switches have been removed. Current runs resume only when their recorded inputs, settings and implementation match. To recover an older interrupted lot, use its original source revision and binary; retain the original archive and manifests. Fresh collection and fixed-pool reevaluation remain available. Never edit an implementation hash to bypass this check.

## Publication footprint

Commit source, templates, frozen task/input definitions, concise protocols, compact proposal exports and provenance hashes. Do not commit generated run trees, build output, local runtime configuration, response caches or nested release archives. The publication package excludes these bulky/private runtime artifacts while leaving the supplied original archive and local paid evidence intact.

Verify the compact data from the repository root:

```bash
(cd experiments/evidence && sha256sum --check SHA256SUMS)
```

The four published lots are selected for distinct interventions. They are not four independent confirmations. Historical qualification, learning and sleep numbers in the ledger are explicitly marked when their original raw archives are not included in this source publication.

## Native causal-delivery suite

The [native causal v2 analysis](genesis/CAUSAL_NATIVE_RESULTS.md) separates the completed 3,456-answer `context-cued` run from the earlier failed native-exposure run. Its compact `answers.csv` supports recalculating descriptive decision contrasts; a new native preflight needs the exact qualified snapshots and the causal v2 implementation. Resume additionally requires the original frozen payloads, audit/checksums and manifest settings. The documentation update alone does not install the implementation extension.

Treat repeated requests, wordings, option orders and mirrored scenarios as clustered observations. Repetition disagreement and option-order sensitivity are different measures. The 12-scenario causal suite has different arms from the old two-domain v4 selector comparison and does not satisfy that earlier preregistered criterion by inheritance. See the recorded archive hash and source-commit/provider-attestation gaps in the causal provenance file.

## Static results page

Open `docs/index.html` in a local checkout, or host the repository root and visit `/docs/index.html`. It is a standalone English HTML/CSS page with no script, external font or tracking request. Relative evidence links expect the repository layout; hosting only the docs subdirectory would omit the sibling evidence files. Publication does not automatically configure or deploy a hosting service.
